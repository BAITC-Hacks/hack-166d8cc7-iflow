# Контекст LLM для рекомендаций Career Quest

## Что получает модель

`build_recommendation_context(employee_id, snapshot, as_of_date)` собирает данные одного сотрудника из одного снимка. Нет специальных веток для известных ID и нет сокращения истории до последних или только завершённых занятий.

- `employee`: все исходные поля профиля, включая 23 навыка Сымбат, дату найма, руководителя, формат работы, язык интерфейса, карьерную цель и дату оценки.
- `current_skills`: отдельно рассчитанные актуальные уровни. Уже учитывают завершения после оценки; отсутствующий навык означает уровень 0.
- `skill_catalog`, `proficiency_scale`: названия, описания и шкала всех навыков.
- `history`: вся эффективная история, включая обязательные мероприятия, отказы, пропуски и повторные попытки. У каждой записи есть полная карточка мероприятия, исходная строка с баллом/прогрессом/отзывом/инициатором и актуальный статус с учётом завершений через API.
- `event_catalog`: все карточки каталога, включая описание, формат, длительность, аудиторию, требования, приросты навыков и даты сессий. Наличие карточки в контексте не делает мероприятие доступным для рекомендации.
- `role_requirements`: полные требования текущей роли, следующего грейда как ориентира и отдельно явно заданной карьерной цели. У каждого блока есть рассчитанные разрывы и критические навыки. При отсутствии следующего грейда или цели соответствующего блока нет.
- `candidates`: только допустимые мероприятия с рассчитанными приростами и проверяемыми факторами; `excluded_events` объясняет исключения.
- `facts`: общие проверяемые факты профиля и каждой записи истории со ссылками на источники. Можно обосновывать рекомендацию опытом других мероприятий, а не только повторениями выбранного курса.
- `unknown_preferences`: неизвестные интересы, свободное время, предпочтения в обучении, карьерное направление при пустой цели и причины незавершения. Предложения вопросов не являются ответами сотрудника.

## Как модель должна рассуждать

Инструкции находятся в `backend/app/ai/prompts.py`. Модель сравнивает критичность пробелов, достижимые приросты и историю, выбирает 1–3 допустимых мероприятия и объясняет выбор минимум тремя видами фактов. Одним из оснований должна быть релевантность навыка выбранного мероприятия.

Оценка за курс, процент прохождения и отзыв сотрудника — разные величины. Завершённый Advanced Python с баллом 65 не требует доведения до 100 или повторного начисления навыка. Историческая дата сессии/зачисления помечена как приближение для расчёта завершения; точной даты окончания в исходном CSV нет.

Отсутствие карьерной цели не означает желания получить следующий грейд. Отказ или пропуск не устанавливает причину поведения. Работа в офисе не означает предпочтения очных курсов, язык интерфейса — языка обучения. Тексты из каталога и профиля передаются в сообщении с данными, а не как системные инструкции.

Ответ содержит рекомендации с фактами, необязательные `hypotheses` и до двух `clarifying_questions`. Гипотезы помечаются `needs_confirmation: true` и ссылаются на известные факты. Причины поведения и предпочтения формулируются предположительно. Ответы сотрудника на вопросы пока не сохраняются: для этого потребуется отдельный сценарий диалога.

## Подключение и просмотр

`GET /api/employees/{id}/recommendations/context` возвращает тот же контекст, который получает рекомендатель. Требует существующую авторизацию: сотрудник видит себя, HR — выбранного сотрудника. Ответ имеет `Cache-Control: no-store`. Для E0047 можно использовать HR-токен из настроек; запрос сотрудника E0001 к E0047 будет запрещён.

`POST /api/employees/{id}/recommendations` собирает контекст и передаёт его `AIClient.refine`. Для подключения провайдера передайте `create_app(settings, ai_client=JSONRecommender(complete))`, где `complete(messages)` вызывает выбранную модель и возвращает строку JSON. Также можно реализовать протокол `AIClient` напрямую. `JSONRecommender` формирует полные сообщения и проверяет ответ. Provider timeout и десятисекундный бюджет нужно обеспечить в конкретном сетевом клиенте.

По умолчанию внешний провайдер отсутствует: при наличии кандидатов возвращается 501, без кандидатов — `no_candidates`, без обращения к модели. Ошибка провайдера, невалидный JSON или неподтверждённые факты возвращают 503 с общим сообщением без содержимого ответа провайдера. Реальные ключи и сетевые вызовы в этом изменении не добавлены.

Проверяются ID, ревизия, дата, допустимость и уникальность мероприятий, число рекомендаций, наличие нескольких факторов и точное совпадение структурированных доказательств с контекстом. Проверка структурированных фактов не гарантирует правдивость всего свободного текста модели; качество объяснений требует отдельной оценки на реальном провайдере. HR-показатели рекомендаций и отображение нового ответа в UI пока не подключены.

## Проверки

`python -m pytest backend/tests -q`

Тесты полного контекста проверяют Сымбат E0047: 23 исходных навыка, 22 записи истории (6 обязательных), 40 карточек событий, 60 навыков в справочнике, точный балл 65 при прохождении 100%, отсутствие повторного начисления старых курсов и обновление навыка после новой активности. Дополнительно проверяются смена роли, Lead без следующего грейда, незнакомый ID, завершение через API, передача полного контекста адаптеру, отвергание выдуманных доказательств и разграничение доступа к контексту.
