# OpenAI: запуск и проверка качества

## Настройка

Backend автоматически читает `.env` в корне репозитория. Переменные процесса имеют приоритет. Файл исключён из Git; ключ не передаётся браузеру. `NVIDIA_API_KEY` пока зарезервирован и не используется; автоматического переключения на другой сервис нет.

```env
AI_PROVIDER=openai
OPENAI_API_KEY=your-secret-key
OPENAI_MODEL=gpt-4.1-mini
AI_TIMEOUT_SECONDS=10
AI_MAX_OUTPUT_TOKENS=1400
AI_AUTO_PREPARE=false
```

Установить `python -m pip install -r backend/requirements.txt` и перезапустить backend. Например: `python -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000`. При Docker: `docker compose up --build`. Compose передаёт настройки только backend.

При открытии профиля frontend запрашивает сохранённую рекомендацию. Если контекст изменился или результата ещё нет, сервер обращается к OpenAI. Модель, версия инструкций и политики входят в ключ кэша. `AI_AUTO_PREPARE=true` дополнительно запускает последовательную подготовку всей команды в фоне; `false` не отключает обработку уже существующей почтовой очереди.

Ключу нужен доступ к Responses API и выбранной модели. Ошибки авторизации, прав, квоты, ограничения частоты, таймаута и неподтверждённых фактов возвращаются с безопасным сообщением. Сырой ответ ошибки и секреты не включаются в API-ошибки.

## Контракт

Используется официальный SDK, Responses API, `store=false`, строгая схема `WireResult`, без инструментов и автоматических повторов SDK. `store=false` не является обещанием отсутствия любых журналов у провайдера.

Модель получает полный связанный контекст и возвращает выбор курсов, уверенность, `evidence_ids` и необходимые вопросы. Объяснения и гипотезы не запрашиваются у модели. Сервер строит текст из проверенных фактов: реальный прирост с учётом предела, критичность, требования, история. Неверные ссылки evidence у допустимого курса восстанавливаются из его фактов; неизвестный ID курса отклоняется.

При таймауте разрешена одна повторная попытка в пределах исходного сетевого бюджета. Обе попытки делят `AI_TIMEOUT_SECONDS`; ошибки авторизации/квоты не повторяются. SDK retries остаются выключенными. Внешняя задержка и успешный ответ не гарантируются; при сбое HR видит статус failed. Результаты проверки после аудита: [QA_FIXES.md](../QA_FIXES.md).

Основной выбор — одна активность. Дополнительные требуют высокой уверенности и отдельного обоснования. Перед сохранением проверяются допустимость, уникальность, 1–3 рекомендации и минимум три разных вида фактов. Отсутствие оснований для основного выбора даёт `needs_clarification` без предложения и письма.

Дополнительная проверка истории: если у выбранной активности не меньше двух незавершённых попыток (`no_show`, `dropped`, `declined`) после последнего успешного участия и причина неизвестна, основной выбор переводится в уточнение. Если такое обнаружено у дополнительного варианта, сохраняется только основной. Это консервативная продуктовая политика, не утверждение о мотивации сотрудника. Полный диалог с сохранением ответа сотрудника ещё не реализован; такие случаи пока требуют ручного разбора.

## Локальные и реальные проверки

Обычный `pytest` использует подставной HTTP-транспорт и не расходует токены. Он проверяет строгую схему, ссылки на факты, таймауты/отказы/квоту, загрузку окружения и отсутствие ключа в ошибках.

Для ограниченного реального прогона (до четырёх запросов):

```sh
python backend/evals/run_openai.py --live --output data/state/openai-evaluation.json
```

Есть три искусственных контрпримера в формате моделей датасета: минимальный Public Speaking с тремя пропусками против критичного System Design; недостающие предварительные навыки; завершённый курс с оценкой 65. Это наши проверочные примеры, не неизвестные профили жюри. Четвёртая проверка — Сымбат из исходного набора.

Можно выбрать один `--case lowest_skill_trap`, `prerequisite_trap`, `score_65_is_completed` или `symbat`. `--timeout 30` меняет таймаут только оценки и помогает отдельно исследовать качество, не меняя настройки приложения. Отчёт сохраняет результат, длительность и доступное число токенов, без ключей. Проверка ожидаемого ID курса не проверяет каждое предложение объяснения.

Живые проверки 23.09.2026 подтвердили доступ к OpenAI и правильный первый выбор в трёх искусственных сценариях после повторов двух запросов с увеличенным таймаутом. При стандартном таймауте 10 секунд два из четырёх запросов завершились таймаутом. Повтор для сценария с оценкой 65 занял около 10,8 секунды. Значит, стабильное выполнение требования о десятисекундном ответе **пока не подтверждено**. На реальном профиле найдена чрезмерная уверенность при повторном предложении незавершённой активности; после этого добавлена описанная выше проверка истории. Она проверяется локально на сохранённом результате и в тестах.

Источники реализации: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
